# 远程数据源改造方案：单活动源

设计基线：2026-09-27，代码提交 `efb4b3f`。本文为待实施设计，不代表功能已经实现。

## 1. 约束与设计决定

用户明确：任一时刻只连接一个远程数据源。保留本地音乐功能，远程类型支持 Subsonic、Navidrome、WebDAV、Emby。

- 界面只有一个“远程配置”入口、一个当前远程源；不做多服务器并行扫描、多远程源混播或服务器管理列表。
- Navidrome 是 Subsonic/OpenSubsonic 适配器的服务器类型，不另写一套重复客户端。
- 本地歌曲与当前远程源可以出现在同一曲库、同一播放队列。
- 同一来源的内网、公网、EasyTier 是候选连接地址，不是多个数据源；同一请求只选择一条线路。
- 保留 `sourceId`。它用于切换前后的歌曲、缓存、收藏、歌单归属，不代表同时连接多个源。
- 切换源后，旧源曲库暂不展示，旧队列条目移出；旧歌曲行、收藏、播放统计和缓存保留。缓存仍受原有全局容量限制。
- 第一版不提供旧源缓存与当前源的混播入口。切回旧源并完成关联后恢复展示；用户可在缓存管理中清理历史缓存。
- 不自动删除远端文件。WebDAV 首版仅列举、读取文件，不执行 PUT、MOVE、DELETE。
- 保留 SQLiteOpenHelper、现有 Compose 页面结构和 Media3；不同时引入 Room、全量依赖注入框架或重写播放器。

这里选择保留历史数据，是为了让用户改配置时不丢收藏和歌单。历史记录是被动数据，不运行连接、不保存活动客户端；是否额外提供“记住多个配置”属于后续产品能力。

## 4. 数据设计与升级策略

### 4.1 来源和当前配置

推荐在 v9 新增以下结构。字段类型与约束为设计目标，迁移 SQL 应通过旧库样本验证后实现。

```text
remote_sources
  id TEXT PRIMARY KEY                  // UUID，资源归属标识
  protocol TEXT NOT NULL               // SUBSONIC / WEBDAV / EMBY
  serverFlavor TEXT                    // NAVIDROME 等展示类型
  displayName TEXT
  username TEXT
  intranetUrl TEXT
  publicUrl TEXT
  serverIdentity TEXT                  // 服务端可提供时保存，不伪造
  protocolOptionsJson TEXT             // WebDAV 根、所选库等；有 schemaVersion
  credentialRef TEXT                   // 指向独立加密凭据记录
  connectionRevision INTEGER NOT NULL // 地址、账号、凭据修改后递增

remote_state
  singletonId INTEGER PRIMARY KEY CHECK(singletonId = 1)
  activeSourceId TEXT NULL REFERENCES remote_sources(id)
```

`remote_state` 唯一一行表达当前活动源，避免多个 `isActive=1`。历史来源行只保留数据归属与非敏感配置；切换后旧会话不驻留，首版不承诺保留旧登录凭据。

地址编辑默认保留 sourceId，但必须区分“同一个服务器改地址”和“替换服务器/账号”。协议变化、明确替换服务器、切换账号应创建新 sourceId；Emby 可用服务端身份辅助校验。没有服务端 ID 时，不因为地址看起来相近就自动认定相同。

WebDAV 身份路径相对稳定的服务根计算，选定扫描子目录只是 scope。改变服务根会改变资源命名空间，应按新来源处理。内外网地址必须指向同一服务根。

凭据单独存储为 Keystore 加密数据；保留并迁移现有 `CredentialCipher` 的兼容逻辑，禁止加密失败回退明文。独立凭据文件加入两套 Android 备份排除规则；本次不改变现有曲库数据库的备份策略。数据库状态与凭据写入跨存储时采用“先安全写凭据 → 事务保存引用 → 清理未引用凭据”，恢复时校验引用，缺失则要求重新认证。

### 4.2 歌曲与稳定标识

对 songs 增加：

| 字段 | 作用 |
|---|---|
| `sourceId TEXT NULL REFERENCES remote_sources(id)` | 本地为 null；远程旧记录未关联时也可为 null，不能据此单独判断本地 |
| `remoteAlbumId TEXT NULL` | 服务端专辑标识，避免不同版本同名专辑混合 |
| `remoteVersion TEXT NULL` | ETag 或已验证的内容版本信息，不是永久歌曲 ID |
| `availability TEXT` | available / missing / unbound；离线不等于 missing |
| `metadataState TEXT` | pending / basic / complete / failed，主要用于 WebDAV |

歌曲远程身份为 `(sourceId, remoteId)`。添加只覆盖 sourceId 非空且 remoteId 非空的唯一索引。新数据的空 remoteId 是解析错误，不能生成一个看似可播放的假 ID。

`Song.isRemote` 判断明确的远程 sourceType 集合；Navidrome 持久化协议仍为 subsonic。旧未关联远程记录不能退化成本地文件。

新歌曲的 path 使用 `remote://<sourceId>/<base64url(remoteId)>`，不含认证信息。这里 base64url 为 UTF-8 编码后的可逆表示，不直接拼接任意路径。旧 subsonic:// path 保持不变，由数据库行的 sourceId/remoteId 解析，避免升级时破坏现有队列 path 兜底和封面键。不要从旧定位符猜当前服务器。

重扫只按来源与远程 ID 命中，不进入 `byIdentity` 兜底；本地扫描原有匹配规则单独保留。跨来源相同曲名可以在 UI 后续分组，但不能覆盖原歌曲行。

### 4.3 旧库迁移

1. 新建表、可空列和索引；保留 songs.id、歌单绑定、喜欢和统计。
2. 将现有 Subsonic 配置迁移为一个来源并设置当前来源。凭据迁移失败标记需认证，不影响本地曲库打开。
3. 只把能确定归属的旧远程行关联到该来源。旧 source 标签与配置吻合可作为依据；仅值为 subsonic、来源冲突或历史配置已丢失的记录，不能一律绑定当前配置。
4. 未确定归属的行保留并标记 unbound；通过后续重新关联流程处理。扫描新曲前先核对可匹配的旧记录，保留其行 ID。
5. 若多个旧行映射到同一组合唯一键，先将冲突行留在未关联状态并记录待处理项；不能用 INSERT OR REPLACE 隐式删除歌曲及级联歌单。该组需完成无损关联处理后再启用对应资源导入。
6. 旧缓存只在归属可确认且文件有效时复用；检测一个缓存路径被多个不同来源引用的情况，不能把可疑文件当成验证成功。
7. 不在 SQLite 升级事务中联网、移动大文件或操作播放器。文件迁移在启动后幂等执行。
8. 从 v6/v7 升级仍必须经过现有认证 URL 清理逻辑；覆盖 v8 和新安装两条路径。

数据库升级失败应整体回滚。跨数据库与文件的迁移记录步骤，允许下次启动继续；本方案不承诺旧 APK 可直接读取新版本数据库。

### 4.4 歌单、艺术家与同步状态

- 本地 `playlists` 与 `playlist_songs` 先保持现状，降低迁移范围。
- 新增 `remote_playlist_bindings(sourceId, remotePlaylistId, localPlaylistId, remoteName)`；按前两列唯一关联。首次导入同名远程歌单创建独立本地名称，如“收藏（远程）”“收藏（远程 2）”，不覆盖已有本地歌单。
- 现有歌单关系主键是 `(playlistId, songId)`，无法表示同曲多次。第一版导入明确去重并提示数量；若要求完整还原远程重复条目，再单独升级为条目 ID 主键，不能宣称无损同步。
- 新增来源隔离的远程艺术家元数据表，旧 `artists_meta` 保留兼容；不把旧表按名称的远程封面直接套到新来源。
- 新增 `remote_sync_runs(runId, sourceId, scopeKey, configRevision, state, startedAt, finishedAt, errorSummary)` 和 `remote_scan_members(sourceId, scopeKey, songId, lastSeenRunId)`，支持完整扫描的范围校验。
- 新增来源资源排除表 `(sourceId, remoteId)`。旧全局歌名/歌手排除规则继续生效；新“移除当前远程歌曲”默认只排除该资源，不能意外屏蔽新源同名歌。

## 5. 单活动会话与切换流程

### 5.1 运行时结构

```kotlin
// 接口示意，不是可直接编译的完整实现。
data class RemoteSessionKey(
    val sourceId: String,
    val generation: Long,
    val configRevision: Long,
)

sealed interface RemoteSessionState {
    data object Unconfigured : RemoteSessionState
    data class Switching(val previousSourceId: String?) : RemoteSessionState
    data class Ready(val key: RemoteSessionKey) : RemoteSessionState
    data class NeedsAuth(val sourceId: String) : RemoteSessionState
    data class Failed(val sourceId: String?, val error: RemoteFailure) : RemoteSessionState
}
```

会话内只有一个不可变配置快照、一个 provider 实例、一组作用域内的任务、一个连接选择状态。每次切换、登出或改变认证/连接配置均使 generation 失效，即使 sourceId 相同也不能复用旧请求结果。

不能只在任务开始时检查活动源。网络返回、批量入库、文件提交、UI 发布时都要核对 key；提交校验与更新在同一协调锁/数据库事务中完成，防止“检查通过后发生切换”的竞态。磁盘迁移不占用长事务，耗时网络操作也不持有数据库写锁。

所有请求带所属会话标签。取消只作用于旧会话，不能对共享 OkHttpClient 无差别 cancelAll。同步 execute 的请求也必须由取消桥调用 Call.cancel()；只取消协程不足以保证连接终止。捕获 Exception 时先重新抛出 CancellationException。

### 5.2 保存并切换

```text
校验新表单格式（不联网）
  → 获取切换锁，进入 Switching，禁止新建旧源任务
  → 若正在播旧远程歌曲：保存恢复点并停止/关闭数据源
  → 取消并等待旧扫描、缓存、封面、歌词请求退出
  → 若无法确认退出：本次切换失败，不启动新源请求
  → 临时认证/探测新源
  → 失败：关闭临时请求，恢复旧配置为可用状态，保持原曲库
  → 成功：凭据就绪后，事务提交来源配置和 activeSourceId
  → 移出旧源远程队列项，保留本地条目的顺序及当前本地播放
  → 失效数据库查询缓存与会话内存缓存，发布新会话
  → 加载“本地 + 新源”曲库，用户启动新源扫描
```

旧远程播放被停止后不自动在后台重新播放；失败时保留恢复点，由用户继续。当前正在播本地歌曲时，不因远程配置切换中断它。

“测试连接”不保存配置。测试另一个来源时也复用暂停旧远程任务的排他流程，测试结束关闭临时连接后恢复旧会话；界面提前说明测试期间远程播放会暂停。这样严格满足同一时刻一个远程源。

重启顺序改为：数据库升级 → 凭据及活动源恢复 → EasyTier 初始化/绑定 → 会话 ready 或 needsAuth → 曲库加载 → 队列恢复 → 当前源封面补齐。离线和需认证时仍可以展示当前源已导入信息并播放有效本地缓存。

## 6. 协议接口与播放链路

### 6.1 统一接口

```kotlin
interface RemoteMusicProvider {
    suspend fun probe(): ProbeResult
    suspend fun listLibraries(): List<RemoteLibrary>
    suspend fun readPage(scope: ScanScope, cursor: String?): RemotePage
    suspend fun getSong(remoteId: String): RemoteSong
    suspend fun resolvePlayback(ref: RemoteSongRef, options: PlaybackOptions): PlaybackRequest
    suspend fun resolveDownload(ref: RemoteSongRef): DownloadRequest
    suspend fun resolveArtwork(ref: ArtworkRef): RemoteRequest?
    suspend fun getLyrics(ref: RemoteSongRef): LyricsResult
}
```

这些类型放在 model/network 的契约包。`RemotePage` 包含下一游标、完整性信息、条目与失败项；目录浏览可作为 WebDAV 的附加接口；歌单/收藏/播放上报作为可选能力接口，不要求所有 provider 伪造空结果。

区分 unsupported、没有歌词、无权限、认证失效和网络错误。能力包含 readPlaylists、writePlaylists、lyricsById、downloadOriginal、transcode 等；seek 能力最终来自具体播放资源，不能只看协议名。

`PlaybackRequest` 包含临时 URL、请求头、MIME、DIRECT/HLS 等类型、实际输出音质和可选有效期/会话标识。认证材料仅在内存，请求对象避免默认 toString 打印秘密。URL 有效期未知时不虚构固定过期时间；401 或明确失效时按策略重新解析，限制重试。

### 6.2 播放集成

1. `PlayerController` 继续管理队列、播放状态及 UI，但不拼接协议 URL。`buildMediaItem` 使用稳定资源标识和元数据，不执行网络探测。
2. `PlaybackService` 注入数据源工厂；本地文件走现有路径，远程稳定定位符走 `RemotePlaybackDataSource`。
3. 数据源 open 时先检查有效本地缓存，再验证 sourceId 属于活动会话，最后解析 URL 和认证。自动续播、seek 重新打开流也走这条链路。
4. `DataSource.open()` 是同步边界：若解析接口是 suspend，只能在播放器加载线程桥接，设置超时，并保证 close/切换可取消底层请求；不得在 Compose/播放器应用线程 runBlocking。正式实现前先做该边界的可取消原型测试。
5. 不使用全局可变请求头。按实际打开的请求设置认证，跨主机重定向不能直接转发账号、Token；候选地址与重定向遵循来源配置和信任策略。
6. HLS 是独立路径：先异步取得播放描述，再创建相应 MediaSource，清单和分片共用绑定会话的数据源。禁止把 m3u8 当普通音频文件下载或用 ProgressiveMediaSource 播放。
7. 暂不支持的编码、转码或不具备 seek 的服务器返回明确结果，不能无休止重试。
8. 歌词、封面返回时检查当前歌曲与会话；旧曲回调不能更新新曲。通知栏封面临时文件也使用稳定哈希，替换当前 32 位 path.hashCode 键。

Media3 当前锁定 1.9.4，OkHttp 为 4.12.0。若使用 Media3 OkHttp/HLS 模块，在版本目录添加与现有 Media3 相同版本的 alias，不借此升级全部依赖。

## 7. 三种服务的具体落地

### 7.1 Subsonic / Navidrome

- 从现有 buildUrl、request、parseSong、getStreamUrl、getCoverArt、getLyrics 抽出实现，去除对全局 config 和数据库的直接访问。
- 用 OkHttp URL builder 构建端点与参数；远程 ID、用户名及歌单参数不能直接字符串拼接。保留 base URL 的反向代理子路径。
- 配置页显示 Navidrome/Subsonic 两个选项，底层协议相同，按 probe 结果探测 OpenSubsonic 扩展。
- 支持选择音乐库；用分页专辑列表等已验证接口替代一次性三级遍历。不同服务器可保留遍历降级，但必须暴露子请求失败。
- parseSong 补齐歌曲自身 artist、albumArtist、bitrate 单位等映射，不能统一用外层艺术家名称覆盖合辑曲目。
- 歌词优先按歌曲 ID，能力不支持时再使用现有 artist/title 查询；回退结果应允许缺失。
- 保留旧 Subsonic 用户的登录和直播放功能，作为新基础层的首个回归样本。

### 7.2 WebDAV

- 表单：服务地址、用户名、密码、服务根、选定扫描目录；首版支持 Basic 认证，Digest 另做明确能力项，不能宣称覆盖全部服务器。
- 使用 PROPFIND Depth: 1 逐层列举，解析 namespace 和逐项 propstat；207 不等于所有文件属性成功。
- 维护目录队列、已访问目录和边界，忽略自身条目，防止循环和越过选定范围；禁止外部 XML 实体。
- URL 以服务端 href 为依据解析，正确处理绝对/相对 href、中文、空格、+、#、%、尾斜杠、编码后的分隔符。不能对整个路径反复 URLDecode/URLEncode，也不能擅自转小写。
- 第一次扫描只使用文件名、大小、类型、修改时间等便宜属性，先让文件可播放。没有音乐标签时不伪造已完成状态。
- 当前 MetadataParser.parse(path) 依赖真实本地文件，不能传 remote:// 或 HTTP URL。第一版在文件缓存完成后复用它；同目录歌词/封面可单独限量获取。
- 后续可增加有字节预算的范围读取标签解析，但需按格式验证；不能把任意截断文件当完整文件交给现有解析器。
- 解析完成只更新元数据，不改变资源 ID/首次入库时间/喜欢/统计；若 ETag/内容版本已变化，丢弃旧解析结果。
- 用实际 Range 请求判断范围读取，不仅信任 Accept-Ranges；处理 206、忽略 Range 返回 200、416、缺失 Content-Length。ETag 不作为内容 MD5 或永久 ID。
- 未提供强验证条件时，首版下载失败从头重试；断点续传后续结合 If-Range 和一致的内容版本实现。

### 7.3 Emby

- 使用用户登录取得 Token、用户标识和服务端身份；DeviceId 在安装范围内稳定。401 进入需重新认证状态，不假定支持 refresh token。
- 按用户权限选择音乐库，分页拉取音频条目；映射时长、码率、多艺术家、专辑艺术家、磁盘号与封面，不直接套用 Subsonic DTO。
- 时间统一换算为 Song.duration 的毫秒；Ticks 使用 Long，转换与上报集中封装并测试。
- ItemId 标识曲库项，MediaSourceId 标识具体媒体源，播放及缓存键必须区分多个媒体版本。
- 第一交付支持设备可解码的直接播放与有权限的原始文件下载；不能直接播放的格式给出明确提示。
- 后续增加 Universal Audio/HLS 转码，并单独测试 seek、断网恢复和媒体会话清理。原文件格式和实际输出格式分别展示。
- 播放开始/进度/停止上报只在当前会话发生，停止旧源时完成或有限等待清理后再连接新源；网络中断时不能承诺服务器立即清理。
- 歌词、歌单写入和收藏同步按目标版本与权限探测；第一版仍使用本地喜欢和本地歌单，不静默向服务器写操作。

## 8. 扫描、缓存和可见范围

### 8.1 扫描任务

`RemoteLibrarySync` 使用会话子 scope，页面退出不导致任务状态丢失。首版保证应用进程存活期间持续扫描；进程退出后标记 interrupted，下次可重新扫描，不声称已具备系统级后台续传。持久后台任务另行按 Android 限制设计。

默认每批 200 首、最多 3 个元数据请求并发作为初始参数，经过测试调整，不作为固定性能承诺。同一活动源只运行一个曲库扫描任务。

流程：抓取一页 → 校验会话 → 记录 seen 成员 → 应用排除规则 → 事务 upsert → 发布进度。全量 JSON 不留在内存；MusicLibrary 的全量内存快照暂时保留，但只在阶段性/结束时刷新，不能每首歌全库 reload。

任务状态明确为 running / succeeded / partial / failed / cancelled / interrupted。未知总数时显示已处理数量，不编造百分比。

首版只新增/更新。启用缺失检测后，只对完整成功、相同来源、相同 scope、相同配置版本的全量扫描标记 missing；权限错误、分页不稳定、部分目录失败均禁止据此清理。标记缺失不物理删除歌曲或歌单关系；显式“清理不可用歌曲”再走现有删除协调入口。

### 8.2 缓存

新缓存布局：

```text
remote_cache/<sourceId>/audio/<sha256(resource + mediaSource + version + outputProfile)>.cache
remote_cache/<sourceId>/artwork/<sha256(artworkRef + version + requestedSize)>.img
```

资源序列化使用固定字段格式，不能用有歧义的裸字符串拼接。缓存条目持久化来源、内容版本、输出规格、完成状态；可新增 `remote_cache_entries` 表，Song.cachedPath 仅作为兼容镜像，不能继续作为唯一可信状态。

保留全局容量与 LRU，不做每源配额。历史缓存进入全局统计与清理范围，但历史资源不触发网络补齐。播放中的文件不被淘汰；下载中间文件不算完成文件。

在途任务使用完整缓存键加会话世代去重。完成后校验会话和资源版本，写入当前任务独有临时文件，成功提交后再更新数据库/UI；取消时关闭流并清理临时文件。禁止新会话接管旧会话 Deferred。

同封面可被多首歌曲引用，删除一首歌曲时不能直接删除仍被其他歌曲引用的封面；按引用/存在性检查后回收。数据更新后清除 ArtworkCache 与 DecodedArtworkCache 中对应旧图或“无封面”的负缓存。

### 8.3 所有查询使用同一个 LibraryScope

```kotlin
data class LibraryScope(val activeSourceId: String?, val revision: Long)
```

可见范围为：本地歌曲 + sourceId 等于活动源且可展示的远程歌曲；旧未关联远程行不自动展示为本地歌。

必须覆盖歌曲、搜索、收藏、最近播放、播放次数统计、专辑、艺术家、歌单歌曲及计数。只过滤 MusicLibrary 不够，因为专辑/艺术家等直接走 DAO。DatabaseHelper 缓存带 scope/revision；旧查询结果不能在切换后写回新缓存。

第一版专辑分组使用本地/远程来源桶；远程优先 remoteAlbumId，无 ID 则使用名称与专辑艺术家。详情路由传 AlbumKey，不能只传专辑名。艺术家可以保持名称聚合展示，但封面从当前范围的一条完整引用取得。

ArtworkRef 至少包含 sourceId、资源种类、远程 ID/相对路径与版本。专辑/艺术家查询先选代表歌曲 ID，再取该行的 path、缓存路径、封面引用；禁止对这些字段分别 MAX 后拼成不存在的组合。

本地歌单中暂不属于当前源的远程条目显示为不可用并保留关系；“播放全部”只加入本地和当前源可播放条目，同时提示跳过数量。活动队列过滤后要重映射 currentIndex，保持重复条目和 originalOrder 的多重集一致，不能直接沿用旧下标。

## 9. 页面与 EasyTier

配置页顶部提供类型选择：Navidrome、Subsonic、WebDAV、Emby。下方仍为单份配置表单，按类型显示目录/音乐库、认证和连接选项。

- “测试连接”：临时测试，结果分认证、目录/曲库权限、读取能力；不保存。
- “保存并使用”：通过切换协调器提交，显示切换状态；失败保留旧配置。
- “同步曲库”：只同步当前源，显示进度与失败详情。
- “移除当前配置”：停止会话并取消活动源，保留本地音乐；是否清理历史远程数据与缓存用独立操作表达。

保留现有本地扫描入口。远程歌单导入/上传根据能力显隐；上传前逐条筛选 sourceId，明确告诉用户跳过了哪些本地或历史来源条目，不按歌名猜服务器上的 ID。

EasyTier 现有配置只有一个转发目标和本地端口，刚好匹配单活动源。增加明确的 boundSourceId；未绑定当前源时不注入候选地址、不唤醒。切换到别的源时旧转发必须退出或解除绑定，不能继续把 127.0.0.1 转发当作新源。

首版保留现有经验证的转发方式。HTTPS 目标不能通过简单改写为 http://127.0.0.1 就宣称兼容；TLS 主机名/SNI、子路径、代理模式需要独立验证，不关闭证书校验。

## 10. 分批实施与验收

| 批次 | 具体交付 | 通过门槛 |
|---|---|---|
| A：来源身份 | model、新表迁移、来源查询、旧数据关联 | v6/v7/v8 与新装通过；本地扫描不受影响；用户数据不丢 |
| B：协议抽离 | core:remote、单会话、SubsonicProvider、统一配置入口 | 旧 Subsonic 导入/播放/封面正常；协议实现不直接写库 |
| C：切换闭环 | 切换协调器、逐请求认证、缓存与队列隔离、所有页面 scope | A→B 切换过程中没有 A/B 任务同时工作，无旧回调污染 |
| D：Navidrome | 能力探测、分页、库选择、元数据完善 | 实际服务器校验数量、合辑、歌词回退和旧 Subsonic 回归 |
| E：WebDAV | PROPFIND、目录选择、流播放、缓存后元数据补齐 | 特殊路径、部分失败、Range 差异、取消与大目录扫描通过 |
| F：Emby 基础 | 用户认证、音乐库、直接播放、允许的下载 | Token 撤销、权限变化、多媒体源、时间单位、来源切换通过 |
| G：体验增强 | HLS 转码、完整远程歌单/收藏同步等 | 单独验收 seek、会话清理、写入冲突与重复条目；不阻塞基础交付 |

自动化验证应围绕行为，不为简单转发函数写镜像测试：

- 数据库：扩展 `SongDaoMergeTest`、`SongDaoStatsAndCacheTest`、`AlbumDaoCompositeKeyTest`，增加真实旧 schema 升级样本及 `foreign_key_check`。
- 身份：重复扫描不增行，换源同 remoteId 不覆盖，旧未关联记录不会被当前配置播放；标签补全不重建资源。
- 协议：使用与 OkHttp 版本一致的 MockWebServer，覆盖 HTTP 错误、Subsonic 业务错误、DAV 混合 propstat、分页边界和 Emby 认证失效。
- 切换：设置可控延迟，令 A 的扫描/下载/歌词在切换时返回；断言旧请求取消且无 B 状态修改，包括 A→B→A 的 ABA 情况。
- 播放：真机测试手动播放、自动续播、seek、后台恢复、通知栏控制、网络切换和旧源退出；JVM 测试不能替代真实解码和服务生命周期验证。
- 缓存：相同 ID 切换源不命中旧文件；磁盘满、取消、内容变更不生成完成项；共享封面不会因删除单曲被误删。
- 页面：搜索/收藏/统计/专辑/歌单计数一致；切换源保持本地播放；队列重复条目与当前下标正确。
- 兼容：至少两种实际 WebDAV 实现、目标 Navidrome/Emby 版本、带反向代理子路径的服务器，并记录版本和配置，不泛称支持所有实现。

建议实施时使用仓库现有 Gradle wrapper 验证 `:core:common:testDebugUnitTest`、`:core:database:testDebugUnitTest` 和 `:app:assembleDebug`；新增模块配置测试依赖后增加对应任务。本文仅修改设计文档，不需要运行构建，协议和真机兼容性尚未验证。
